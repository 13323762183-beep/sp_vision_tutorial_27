# 项目理解报告

## 1. 图像生命周期与所有权

`ImageSequenceSource` 使用 `buffer_` 模拟相机反复写入的内部图像缓冲区。每次调用 `next()` 时，新图像通过 `copyTo(buffer_)` 写入这个缓冲区。若直接执行 `frame.image = buffer_`，`cv::Mat` 只复制头部并共享底层像素数据（浅拷贝），因此读取下一帧时可能覆盖已经进入队列的旧帧图像。原代码保留的校验值仍是旧图像的校验值，于是 worker 可能检测到损坏。

改为 `frame.image = buffer_.clone()`。`clone()` 为该帧分配独立的像素内存并深拷贝。之后图像源继续复用 `buffer_`，已经交给队列的 `Frame` 仍拥有有效且内容不变的像素数据。生产者通过 `std::move(frame)` 交给队列，避免不必要的对象拷贝；移动 `cv::Mat` 对象不会使它重新共享相机的缓冲区。

## 2. 并发处理与恰好一次

生产者顺序生成带有唯一 ID 的 `Frame`，调用 `BlockingQueue::push()` 将其入队。`push` 在互斥锁保护下添加元素，并唤醒等待线程；多个 worker 调用 `pop()` 取帧。`pop` 同样在互斥锁保护下移动并移除队首元素，因此一个队列元素最多会被一个 worker 取走。生产者对每个成功读取的帧只调用一次 `push()`，正常运行时不会重复入队。

图像源耗尽时，producer 调用 `queue_.close()`，它唤醒全部等待的 worker。队列关闭不丢弃原有元素：只要队列非空，`pop()` 仍会返回一帧；当队列已经空且关闭时，`pop()` 才返回 `false`，worker 循环结束。正在处理图片的 worker 会处理完已取出的图片，然后继续尝试取帧。因此正常完成时所有已入队帧都会被处理并保存一次。通过唯一帧 ID 形成独立文件名，不会因为不同 worker 并发执行而覆盖其他帧的结果。异常情况下程序会记录异常并在 `wait()` 中向调用者报告，不能将异常退出视为成功完成。

## 3. 共享统计数据

生产者调用 `onProduced()`；多个 worker 调用 `onProcessed()`、`onSaved()` 和 `onCorrupted()`；主线程通过 `statistics()` 间接调用 `snapshot()`。原实现中的递增是“读旧值—延迟—写新值”，不是原子操作。两个线程可能读到同一个旧值，随后写入相同的新值，导致计数丢失；无同步的并发读写也形成 C++ 数据竞争。

我在 `Statistics` 中加入 `mutable std::mutex mutex_`，所有计数更新都用 `std::lock_guard<std::mutex>` 保护。`snapshot()` 也用同一把锁，在持锁期间一次性读取四个计数，保证快照中的每个值不会与正在进行的写操作发生竞争。`mutable` 允许 `snapshot() const` 锁定互斥量，而不会改变统计对象的逻辑状态。

## 4. 线程关闭协议

**显式 `wait()`：** `start()` 先创建多个 worker，再创建 producer。producer 读取并入队所有图像，然后关闭队列。调用 `wait()` 时，主线程首先 `join()` producer，等待其结束；然后调用队列的 `close()`（重复关闭也是安全的）并依次 `join()` 所有 worker。worker 会处理完队列中剩余的元素，观察到“队列已关闭且为空”才退出。所有线程加入后，`wait()` 才返回；若线程中发生异常，异常会被保存，并在全部线程收回后重新抛给调用者。

**直接析构：** `Pipeline::~Pipeline()` 调用不抛异常的 `joinThreads()`。它先等待 producer 结束，再关闭队列并等待所有 worker 退出。这样在队列、图像源、处理器等成员析构前，后台线程已经停止访问这些成员，不会产生悬空引用，也不会由于仍有可 `join` 的 `std::thread` 被销毁而触发 `std::terminate`。producer 无论正常完成还是抛异常，都负责关闭队列并唤醒 worker，避免 worker 永久等待。

`wait()` 可以重复调用：对已经加入的线程，`joinable()` 返回 `false`，所以不会重复 `join`；但如果此前保存了异常，重复调用仍会重新抛出该异常。`start()` 只允许调用一次，再次调用会抛出 `std::logic_error`。若启动线程的过程中发生异常，`start()` 会关闭队列、回收已创建的线程并重新抛出异常。本实现假设图像源和图像处理操作会最终返回或抛异常；若底层操作永久阻塞，普通 `join()` 不能强制将其取消。
